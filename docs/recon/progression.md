# Recon: Profile, mastery, stats, leaderboards, replays, news, patch notes, inbox, events ("the data screens")

**Score: 4.5/10** — 19 defects (5 critical)

## The single worst thing

There are no pictures anywhere in the domain. Every place that should carry art carries a letter, a glyph, a text chip or a coloured blob instead: the profile avatar is the string `displayName.charAt(0)` on a grey disc (profileScreen.ts:171), the ten faction Mastery tiles have no crest and no faction colour, the 20-row Mastery reward ladder renders a Faction Pack as a grey text pill and the word "Locked" twenty times, event key art is `radial-gradient(circle, var(--event-accent), transparent 72%)` with one glyph in it (screens.css:3603), news articles have no hero image, and the leaderboard has no rank medal. This is an art-driven collectible card game whose entire progression surface is a database admin panel in a neon gradient. Hearthstone puts your hero portrait in a gold frame on every screen you own; MTGA's Mastery track is a rail of orbs showing the actual reward items; Gwent's Journey is a painted road. Fix the picture problem and half the other defects stop mattering.

## Defects

### 1. [CRITICAL] The profile avatar is a monogram letter on a flat grey disc with a canvas-stroked ring. No portrait, no frame art, no rank medal, no season, no banner. `profile.displayName.charAt(0).toUpperCase()` rendered at 2rem inside `background: color-mix(in srgb, var(--c) 26%, #14101f)`.

- **Where:** src/ui/screens/profileScreen.ts:168-174 (markup), :59-78 (paintFrame), src/ui/theme/screens.css:2384-2404
- **Why it fails:** §1 (nothing is flat — the disc is a solid colour-mix fill with a 3.5%-width stroke and no gradient, no rim light, no contact shadow) and §5 (this is the identity screen and it is styled like a Gmail contact chip). Hearthstone frames your hero portrait in a carved gold medallion with your rank badge pinned to the rim; MTGA gives you an avatar plus a tier crest plus pips; Gwent animates the border. HYPEBOUND ships a letter.
- **Fix:** Build an avatar composite: 1) a portrait plate that draws the player's most-played leader's existing card art cropped to a circle (the art is already loaded for the card renderer and the Gallery screen), 2) the `paintFrame` canvas upgraded from a single `ctx.arc` stroke to a two-pass ring — outer bevel stroke at 8% lightness plus an inner 1px `rgba(255,255,255,0.35)` highlight arc from 200deg to 340deg so the light comes from top-left like every panel, 3) a rank/level medallion replacing the plain `Level 27` text, drawn as a hexagonal plate with the number in tabular display type, 4) keep the monogram only as the genuine fallback when no leader has been played.

### 2. [CRITICAL] Replay Theater's timeline scrubber is an unstyled `<input type="range">`. It renders as a Chrome-blue (#007AFF) track with a blue circular thumb — a colour that appears nowhere else in the palette — sitting under a magenta/violet UI.

- **Where:** src/ui/theme/screens.css:1089 (`.replay-controls input[type="range"] { flex: 1 1 auto; }` — the only rule that touches it), src/ui/screens/replayScreen.ts:184
- **Why it fails:** §7 names this exactly: "a default OS scrollbar in a fantasy card game is a tear in the world". A default OS slider is the same sin and louder, because it is 900px wide and the brightest saturated object on the screen — which also breaks §6's "the most saturated thing on screen should be the thing that matters most". Gwent's and MTGA's replay/animation-speed controls are bespoke tracks with a carved groove and a lit thumb.
- **Fix:** Style it fully: `appearance:none` on the input; `::-webkit-slider-runnable-track` / `::-moz-range-track` as a 6px groove — `linear-gradient(180deg, rgba(0,0,0,0.5), rgba(255,255,255,0.04))` with `inset 0 1px 0 rgba(255,255,255,0.08)`; a filled portion driven by a `--progress` custom property updated in the `input` handler; `::-webkit-slider-thumb` as an 18px plate with a top-left key highlight, a 1px black bottom edge and an accent glow. Add per-turn tick marks along the groove (`repeating-linear-gradient`) so the timeline reads as turns, not as a volume control.

### 3. [CRITICAL] The primary list rows on four screens are non-focusable `<li>` elements with click listeners bolted on — no `tabindex`, no `role`, no keydown handler anywhere in these files. Mastery tracks, news articles, inbox messages and patch releases cannot be reached or activated by keyboard, and a screen reader announces them as list text, not controls.

- **Where:** src/ui/screens/masteryScreen.ts:98 and :114 (handler at :367-378); src/ui/screens/newsScreen.ts:83; src/ui/screens/inboxScreen.ts:106; src/ui/screens/patchNotesScreen.ts:154
- **Why it fails:** §9 hard constraint: "Accessibility is not negotiable… keyboard focus is always visible", and §5 requires focus-visible on every interactive element. There is nothing to focus. Note this is inconsistent inside the same codebase — replayScreen.ts:330 correctly builds `<button>` rows, so the pattern is known and was simply not applied. All three reference games are fully controller/keyboard navigable end to end.
- **Fix:** Convert each row to `<button type="button">` (as replayScreen already does), or at minimum add `tabindex="0" role="button" aria-pressed`. Add the same `:focus-visible` treatment the rest of the app gets, plus roving-tabindex arrow-key navigation within each list so a 20-row Mastery grid is not 20 tab stops. Add `aria-current` for the open/selected row and give the aria-hidden unread dot a real text alternative (`<span class="sr-only">Unread</span>`).

### 5. [CRITICAL] The entire domain has zero motion. `grep` for `animation:` or `@keyframes` past line 2200 of screens.css — where profile, mastery, stats, gallery, leaderboards, inbox, news, patch and events all live — returns nothing. The only transition is `.mastery-bar > span { transition: width 0.3s ease }` (screens.css:2298) and the only hover state on any list row in nine screens is `.replay-entry:hover` (screens.css:1013).

- **Where:** src/ui/theme/screens.css:2200-3811 (no keyframes, no entrance animations, no stagger); hover states absent for `.mastery-track`, `.news-row`, `.mail-row`, `.patch-version`, `.event-mission`, `.event-shop-row`, `.stats-row`, `.profile-slot`
- **Why it fails:** §3 in full — "nothing snaps", "everything overlaps, stagger by 30-60ms", "idle is never dead", "secondary motion is the single biggest gap between animated and alive" — and §7's "nothing ever pops in". Ten mastery tiles, 22 replay rows and 20 ladder rows all appear on the same frame. §5 requires a designed hover on every interactive element and eight row types have none. In Hearthstone every quest row lifts and lights on hover in ~100ms; in MTGA the mastery track nodes fill sequentially with a travelling spark.
- **Fix:** 1) A shared `stagger(container, selector, {step: 40, from: 'top'})` helper that assigns `--i` and a `rise-in` keyframe (`translateY(10px)` + `opacity 0` → 0, `cubic-bezier(0.2,0.8,0.2,1)`, 260ms, delay `calc(var(--i) * 40ms)`), applied to every list in the domain. 2) One shared `.row-interactive` mixin: 110ms hover that lifts 1px, brightens the top-edge highlight and warms the border — never opacity alone. 3) An idle specular crawl on hero panels (8s, very low amplitude). 4) Progress bars animate from their previous value on mount with a leading glow that overshoots ~4% and settles. All of it gated behind the existing `:root[data-reduced-motion="true"]` selector and `@media (prefers-reduced-motion: reduce)`.

## Plan

1. Build the shared foundation first, before touching any screen. One module of surface/motion/numeric primitives (see sharedNeeds) plus a pinned `formatters.ts`. Nothing else in this plan should be started until these exist, or nine screens will each grow their own bevel.
2. Fix the four hard-constraint breaches, in this order: (a) convert `.mastery-track`, `.news-row`, `.mail-row`, `.patch-version` to real focusable buttons with roving arrow-key navigation and `aria-current`; (b) style the replay `<input type=range>` completely (track, fill, thumb, turn ticks); (c) kill `String(undefined)` in the patch-notes economy table and map config paths to human labels; (d) pin every date formatter to `en-GB`. These are the defects that fail the screenshot test in the first second.
3. Solve the picture problem. Build one procedural art generator (canvas → data-URI, cached) that produces: circular avatar portraits from existing leader card art, event key-art banners, news hero images, reward-item plates and faction crest rings. Wire it into profileScreen's avatar, eventsScreen's `.event-key`, newsScreen's article header, and the mastery ladder rows.
4. Rebuild the Mastery ladder as a reward track: milestone nodes at ranks 5/10/15/20 drawn larger with a rim glow, each rung showing its actual reward art, faction colour and crest driven from `FACTION_COLOR` and the shipped crests, a gradient progress bar with per-rank tick marks, and the duplicate rank integer removed in favour of a gift-glyph unclaimed badge.
5. Design the rank/tier object and put it everywhere: a canvas-drawn crest plate with a tier gem, shown on the profile hero panel, the Leaderboards screen (as local standing, with a silhouetted top-200 ladder behind a truthful 'waiting on the season server' plate), and the replay detail header. This single object is what makes the domain read as a competitive card game.
6. Make Statistics visualise. Add a cumulative win-rate canvas chart with axis, grid and a sample-confidence band; convert the trend strip to a height-varying sparkline so win/loss/draw is carried by shape as well as colour; give bars a gradient, an inner highlight and a bright cap; desaturate all faction bars except the hovered row.
7. Unify layout. One `.data-body` container with a single max-width and gutter token applied to all nine screens; wrap the events rows in real panels; add `.scroll` plus a bottom fade mask to every overflowing pane; verify every screen at 1280×720 and at 844×390 landscape and fix the clipping.
8. Apply the three-tier surface system and the noise texture to every panel in the domain, give each screen its own desaturated, blurred, parallaxed ambient variant so there are four resolvable depth planes, and add contact shadows under every raised object.
9. Add the motion layer last, on top of a static build that already reads correctly: `stagger()` on every list mount, a single `.row-interactive` hover mixin (110ms, lift + edge light + border warm), animated progress bars with a settling overshoot, an idle specular crawl on hero panels, and a designed double-ring focus animation. Gate all of it behind the existing reduced-motion selector and re-verify with the flag on.
10. Sweep the copy: strip every `§x.y.z` from player-facing strings and rewrite those paragraphs in-world, route mode ids through `MODE_NAME`, fix `Play ai` and `1 turns`, add `sr-only` text to unread dots, raise the event Buy button to a 44px target, and add tabular figures to every number.
11. Re-shoot all nine screens through `scripts/shot.mjs` at 1600×900, 1280×720 and 844×390, in both populated and genuinely empty states, and put them side by side with the reference set before claiming a score.
